# Handoff: 精度向上策 項目3 — 候補提示の取りこぼし対策（和集合提示）

- 日付: 2026-11-04
- 証拠種別: 記録済み selection run のオフライン再評価（生成なし）。埋め込みランキングは記録値、BM25 は決定的再計算。
- 結論: **採用**（subset 構成の推奨を「emb-prefix top-12 ∪ bm25 top-5」に更新）。holdout 含有率 88.2% → 94.1%、提示増加は平均 +1.12 件。

## 方式

- 新規 `bench:selection-union`（`bench/selection/union.ts` + CLI）: 記録済み selection results.json を読み、emb-prefix top-12 ∪ bm25 top-k（k=3..6 走査）の提示集合について、必要 entry の含有率・提示件数・追加カードの passage 文字数（プロンプト増の代理指標）を測る。
- BM25 は Provider 不要の決定的計算のため、実験/本番と同一の index 実装（`createBm25Index`、cardPassages への文字 n-gram BM25）でローカル再計算した。再計算の正しさは、記録に bm25 ランキングが残る dev（Wave B 実験）で照合し **60/60 完全一致**。ケース集合・required が記録と再導出で一致しない場合は分析自体が停止するガード付き。
- 提示集合は emb-prefix top-12 の superset（構成上、含有は単調に増えるのみで悪化しない）。

## 判定

- 採用条件「holdout 含有率が 88.2% を明確に上回り、提示増加が +数件以内」を満たす: 94.1%（+5.9pt、34 件中 2 件回復）、平均提示 13.12 件（+1.12）。dev でも同方向（95.0% → 96.7%）で再現し、悪化ケースは構成上存在しない。
- 適用範囲: これは **subset 提示を使う場合の構成推奨**の更新である。既定提示（全カード）は Wave C の判定どおり変更しない。ただし subset を使う場面での提示漏れ実害（Wave C で 2/60）は、この和集合で dev 3 件中 1 件・holdout 4 件中 2 件まで減る。
